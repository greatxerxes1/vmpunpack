Одна команда превращает упакованный x64 PE в загружаемый образ, пригодный для анализа.

vmpunpack запускает сэмпл внутри пропатченного эмулятора [sogen](https://github.com/momo5502/sogen) —
тот проходит мимо анти-VM и анти-отладочных проверок, из-за которых VMProtect отказывается работать в
any.run, CAPE и на живом железе, — доводит распаковщик до **оригинальной точки входа (OEP)**, снимает
там дамп памяти, собирает PE для IDA/Ghidra и вытаскивает индикаторы компрометации.

> **Он распаковывает, но не девиртуализует.** Виртуализованные VMProtect функции остаются байткодом
> виртуальной машины. На выходе — рабочий образ с нетронутой VM, а не исходный ассемблер до VMP.

## Установка

```bat
git clone https://github.com/milk-analyzer/vmpunpack.git
cd vmpunpack
setup.cmd
```

`setup.cmd` скачивает две сторонние части, которые этот репозиторий не распространяет, — около 500 МБ,
один раз:

- **эмуляционный рут** с [sogen.dev](https://sogen.dev/root.zip): снимок пользовательского окружения
  Windows, на котором стартует эмулятор;
- **пропатченный эмулятор** из [milk-analyzer/sogen](https://github.com/milk-analyzer/sogen/releases/tag/vmpunpack-1.0.0),
  зафиксированный по SHA-256. Стоковый sogen не подойдёт — хуки распаковки живут в эмуляторе, а не в
  этом Python, — и эта сборка под GPL-2.0, поэтому её исходник опубликован в
  [ветке `vmpunpack`](https://github.com/milk-analyzer/sogen/tree/vmpunpack) того же форка.

`setup.cmd --check` в любой момент проверит уже установленное. `--analyzer-url <zip>` подставит вашу
собственную сборку. Подробности в [THIRD_PARTY.md](THIRD_PARTY.md).

### Требования

Windows x64, Python 3.8+. Больше ничего: инструмент использует только стандартную библиотеку, чтобы
работать на закрытых аналитических виртуалках.

## Запуск

```bat
RUN_ME.cmd C:\samples\thing.exe
```

Результат появится в `<sample>_unpacked\` рядом с сэмплом.

> **Запускайте по одному сэмплу за раз.** `C:\dumps` — фиксированный путь, вшитый в эмулятор, поэтому
> его разделяют все запуски на машине. Два одновременных запуска будут обнаружены и отклонены, а не
> молча перемешаны.

### Флаги

| флаг | смысл |
|---|---|
| `-o OUTDIR` | каталог вывода (по умолчанию `<sample>_unpacked`); очищается от старых артефактов при каждом запуске, поэтому не должен быть `C:\dumps` |
| `--run-payload` | выполнять дальше OEP и фиксировать поведение вместо остановки на ней |
| `--nodelay` | нейтрализовать анти-песочные задержки `NtDelayExecution` |
| `--tsc 0x8000` | увеличивать rdtsc на заданный шаг при каждом вызове, схлопывая циклы задержки на rdtsc |
| `--oep 0xRVA` | задать RVA точки входа вручную, в обход эвристики |
| `--late N` | дополнительно снять `unpacked_late.bin` и `heap.bin` через N базовых блоков после OEP (конфигурация, расшифрованная во время работы) |
| `--timeout SEC` | ограничение времени, по умолчанию 300 |
| `--sogen DIR` / `--emuroot DIR` | пути к движку, если он лежит вне рабочей копии |

### Результат

| файл | что это |
|---|---|
| `<name>.unpacked.exe` | восстановленный PE, точка входа выставлена на настоящую OEP |
| `unpacked.bin` / `.meta` | сырой образ памяти плюс база, SizeOfImage, точка входа и OEP |
| `iocs.txt` | домены, URL и IP-адреса, отдельным разделом на каждый дамп |
| `unpacked_late.bin`, `heap.bin` | только с `--late` |

Восстановленный PE — **аналитический** образ: его таблица импорта содержит адреса эмулятора, поэтому без
восстановления IAT в духе Scylla он не обязан запускаться где-либо ещё.

Поиск индикаторов читает каждый дамп и как однобайтовый текст, и как UTF-16 при обоих выравниваниях,
так что URL и IP в широких строках тоже находятся. Хосты фильтруются по заякоренному списку заведомо
шумных доменов: C2 вроде `windows-defender-update[.]top`, лишь похожий на майкрософтовский, попадёт в
отчёт, а не будет отброшен.

## Как это работает

1. **Бэкенд `unicorn` и `--no-inst-precision`.** По умолчанию sogen ставит хук на каждую инструкцию;
   если дать работать JIT-компилятору TCG, распаковщик со всей распаковкой отрабатывает примерно за две
   минуты вместо «никогда».
2. **Определение OEP.** Хук на исполнение ставится на оригинальную секцию кода — исполняемую секцию с
   наименьшим RVA, не содержащую точку входа упаковщика. Первое попадание туда и есть OEP. Все адреса
   берутся из заголовков самого сэмпла, ничего не захардкожено.
3. **Заполнение пропусков в ординалах.** Импорты просматриваются на записи `#ORD`; если в DLL из
   эмуляционного рута этому ординалу соответствует пустой слот экспорта, он направляется на заглушку
   `ret`, чтобы загрузчик гостя смог его разрешить. Без этого свежий сэмпл падает с
   `STATUS_ORDINAL_NOT_FOUND` (`C0000138`).

## Ограничения

- Это не девиртуализатор.
- Полная виртуализация программы, многоступенчатые загрузчики и трюки с TLS-колбэками могут потребовать
  `--oep`, `--late`, увеличенного `--timeout` или ручной работы.
- **Живой C2 обычно существует только во время выполнения** (например, резолвится через DoH) и в дампе
  отсутствует. `--run-payload` работает по мере возможности: настоящей сети у эмулятора нет.
- Только x64. 32-битные цели отклоняются, а не разбираются неверно.
- Если упаковщик затирает собственную страницу заголовков перед переходом на OEP, собрать загружаемый PE
  невозможно; сырые `unpacked.bin` и `.meta` при этом всё равно сохраняются для ручной сборки.
